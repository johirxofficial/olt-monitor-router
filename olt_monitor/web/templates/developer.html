Deploy on a fresh Ubuntu / Debian server
  1. Install prerequisites: 
    sudo apt update
sudo apt install -y python3 python3-venv python3-pip mysql-server unzip
  2. Copy the bundle to the server and unzip it: 
    unzip olt-monitor-router-*.zip -d ~/
cd ~/olt-monitor-router
  3. Run the installer (twice on a brand-new machine: the first run creates .env): 
    ./install.sh
  4. Fill in .env (MySQL credentials, first device seed) and run ./install.sh again.
  5. Open http://<server-ip>:5002/setup and create the super admin.
  6. Add your OLTs / routers on the Devices page, set the site name in Settings, then take a first SQL export.
Full details: docs/INSTALL.md in the bundle. Roles and daily use: docs/USERS.md.
Add a new OLT

Most OLTs need no Python change:

  1. Devices → Add OLT: host, SNMP port/version, community, brand and PON type.
  2. Click Test to verify SNMP reachability.
  3. Discover the optical OIDs once: 
    .venv/bin/python tools/discover_olt.py --olt "<OLT name>" --autoconfig
  4. If interface names differ, set the per-device classify regexes (uplink_regex, pon_regex, onu_regex, vlan_regex).

Update any file safely
  1. Take a backup: tar -czf ~/olt-backup.tgz ~/olt-monitor-router and a SQL export in Settings.
  2. Edit the file on the server or upload a new bundle and copy only the changed files.
  3. Never overwrite .env, config/config.yaml, config/optical_oids.yaml or data/ — they belong to this installation.
  4. Reinstall dependencies and apply migrations: 
    ./install.sh
  5. Restart and verify: 
    systemctl --user restart olt-monitor-router
./status.sh

A bundle can be pushed with tools/deploy_remote.sh, which keeps local state and restarts the user unit. Browse and read any shipped file on the file browser.
